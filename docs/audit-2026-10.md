# Security and performance audit, October 2026

## Scope

The current code on `main` (commit e717cbb), read from the source. Areas, as assigned:

- Inputs from outside the app: the `library://` URL scheme, the Services entries (Add to Library for text and files), drag and drop, and imported bookmark files (`BookmarkImport.swift`). `LibraryBackup.swift` is not on `main`; it belongs to the backup branch.
- Runtime commands: Terminal items (`Opening.swift`).
- Network: favicon fetch (`Favicon.swift`), copied GIF download (`ClipboardHistory.swift`). The update check is not on `main`.
- Storage: `~/.library` permissions, `bookmarks.json`, `clipboard.json` (`PinnedFile.swift`, `ClipboardKey.swift`).
- Clipboard privacy filters, logging, and temporary copies.
- Hotkeys and the event tap (`HotKeys.swift`).
- Entitlements, signing, Info.plist (`build.sh`).
- Dependencies.
- Performance of the hot paths: the menus, Quick Open, the manager, icon lookups, favicon scheduling, caches, timers and observers, disk writes, and startup.

Not on `main` and so not audited: the update check, iCloud sync, backup and restore, the Touch ID lock. The folder/templates, duplicates/bulk edit, Quick Open snippets, and clipboard loading branches were not touched except where a finding required it, as noted per finding.

## Method

Each area was read in the source. For each suspected issue, a one-line reproduction note (an input or a sequence) was written, then a decision was made on whether code reading confirms it. Only confirmed issues were fixed. Each fix has a check in `Tests/Checks/main.swift`. Each performance fix has a timing in `Tests/Bench/AuditBench.swift` (median of 9 runs, printing only). Verification: `./test.sh` passes, including the theming lint and symbol check; `swift build -c debug` adds no warnings (only the existing linker search-path warnings from the environment); `./build.sh` succeeds.

Limits of the measurements: the sandbox has no network, so the favicon and GIF downloads were verified against a local HTTP server with a throwaway harness outside the repository, not timed in the suite. The Accessibility, screen, and Terminal behavior needs the GUI and was not run.

Checked and found clean (security):

- Command arguments (`splitArguments`) go to the process as argv. No shell is involved for apps and URLs.
- `library://` never runs a command. `item(named:)` excludes commands. Intents that run a command ask for confirmation (`IntentLogic`, `LibraryIntents`).
- Path traversal: the favicon cache is named by host, which cannot contain `/`. Temporary files use UUID names.
- Bookmark import: nesting capped at 64 (`BookmarkImport.maxDepth`), only http and https kept, malformed data throws and does not crash. The import file is one the user chooses.
- `PinnedFile`: ChaChaPoly with a random nonce and a verified tag. No write path can save plain text, because `savePinned` requires the key. Writes go to a 0600 temporary file, then `rename`. A damaged file is moved aside. The key is a random 256-bit Keychain item, `WhenUnlockedThisDeviceOnly`, and its length is checked on read.
- Logging: `NSLog` calls record state and error descriptions only. None logs clipboard text or addresses.
- Privacy filters: concealed, transient and auto-generated types are skipped before capture. Password managers are matched by the frontmost app at the time of the poll, which is up to half a second after the copy. That gap is a known limit, noted here.
- Event tap: it swallows only events that match a configured shortcut. Without access it is not created, so nothing is swallowed. A watchdog re-enables it or drops it.
- Installer: `/bin/sh -c` with the path passed as `$0`, so there is no injection.
- Entitlements and signing: no entitlements file, so nothing beyond the defaults is granted. The URL scheme is `library` only. `NSServices` has two messages. Ad-hoc signature with a fixed identifier (`build.sh`). Hardened runtime is not enabled; this is not changed, since the release workflow depends on the signing setup.
- Dependencies: none. `Package.swift` has no dependencies, and every import is a system framework.
- Force unwraps and `fatalError`: the remaining force unwraps use constant URLs, or `QLPreviewPanel.shared()`, which returns a panel. `WindowFrameAutosave.init(coder:)` is unreachable.

Checked and found acceptable (performance):

- `LibraryStore.icon(for:)` with a color tag draws the dot in a drawing-handler image on every draw. A cache would hold a rasterized image and freeze the dynamic colors, so it was not changed.
- `Timer`, `NotificationCenter`, `NSEvent` monitor and `DispatchSource` teardown: Quick Open's cleanup list covers its observers, monitors and timer. `ClipPreview.discard` removes its monitor and observer. `HotKeys` removes the tap and its watchdog. `ClipboardHistory` stops its timer when history is off. The singletons are never released.
- Startup: `ClipboardHistory` decrypts `clipboard.json` synchronously and `LibraryStore` reads `bookmarks.json`. Both are small. Icon fetching, Spotlight indexing and hot key registration are deferred.
- Writes: saves are debounced to 250 ms, the Spotlight index is checked against a digest, and `reloadIfChanged` compares a stamp before it reads the file.
- Quick Open search: the index is rebuilt only when the library changes (see the existing benchmark, about 0.4-0.7 ms per query at 5,000 items).

## Top risks for a human to review

1. S-10: any web page can open library items by name, including apps with saved arguments. Decide whether `library://open` needs confirmation.
2. S-11: the clipboard link and Quick Open open any scheme with a host. Decide which schemes are allowed.
3. P-03 and P-04: main-thread work while Quick Open is open and on every copy. The new favicon download path was verified against a local server only, not against real sites.
